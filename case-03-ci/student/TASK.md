# Контекст

У рабочего Python-проекта пока нет автоматической проверки изменений.

# Задача

Создать `.github/workflows/ci.yml` с запуском на `push` и `pull_request`: checkout, установка Python, dependencies и обязательный `pytest`.

# Что должно получиться

Первый run зеленый. Позже преподаватель внесет контролируемое изменение: следующий run должен показать понятное падение, а после вашей диагностики и исправления — снова пройти.

# Ограничения

Не использовать secrets, deployment, registry или готовый workflow из закрытых материалов.

# Что разрешено использовать

Git/GitHub, документацию GitHub Actions, локальный pytest и логи Actions. Ruff необязателен.

# Что сдавать

Ссылки на failed run и последующий successful run; кратко: какой step упал, что показал log, какова причина и что изменено; файл workflow и история Git.

# Критерии готовности

Workflow находится в `.github/workflows`, реагирует на оба события, устанавливает зависимости и запускает pytest; красный и восстановленный зеленый runs подтверждены ссылками и объяснением.
